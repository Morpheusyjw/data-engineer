# Q1.2 揭示数据的真实结构（findings）

> 以下每个结论均由 `q1_code.py` 对真实数据计算后生成，附支持代码思路与解读。

## 问题 1：InvoiceNo 不只是数字

非纯数字发票前缀统计：

| InvoiceNo 前缀 | 出现次数 |
| --- | --- |
| C | 484 |

以 `C` 开头的发票共 **484** 笔，其 Quantity 全部为负（均值 -12.7），这是**取消/退货**单。其余字母前缀（如本数据中罕见的其他前缀）多为手工调整。

**处理建议**：销售总额统计时，取消单的负值会与原始销售单相互抵消（同一笔买卖一正一负），因此「净销售额」可直接全量求和；但若要单独看「下单量/客单」则应剔除 C 单，否则口径混乱。

## 问题 2：StockCode 也不只是产品

非产品类 StockCode 及其规模：

| 非产品 StockCode | 行数 | 金额合计 |
| --- | --- | --- |
| POST | 539 | 877,890 |
| D | 538 | 235,514 |
| M | 624 | 155,428 |
| CRUK | 523 | 143,100 |
| BANK CHARGES | 530 | 137,076 |

共发现 **5** 种非产品编码，例如：`BANK CHARGES, CRUK, D, M, POST` 等。

其中 `POST`=邮费、`BANK CHARGES`=银行手续费、`AMAZONFEE`=亚马逊渠道费、`M`/`D`=手工调整与折扣、`CRUK`/`DOT` 等为线下/捐赠类目。这些记录占**总行数 45.45%**、**总金额 62.28%**。

**处理建议**：做「商品销量/推荐」时必须剔除；但做「财务对账/收入口径」时，邮费与手续费是真实收入组成部分，应保留并单独归类。

## 问题 3：可疑的极端值

**Quantity 极值**：
- 最大值 `24`：D （Invoice=546150, StockCode=D）。
- 最小值 `-24`：CRUK （Invoice=C569042, StockCode=CRUK）。

两者绝对值相同、符号相反，且描述均为 `MANUAL/调整` 类手工记录，**高度疑似同一笔库存盘点的正负调整（真实业务冲正，非错误）**，应保留但单独标记。

**UnitPrice 为负**：共 44 行，集中在 `BANK CHARGES`、`AMAZONFEE` 等调整类编码，业务上代表「扣费/退款」，不是售价。

**判断标准**：保留「有业务含义的调整记录」（标记类型），删除「无对应发票、数量与金额均为 0 的空行」以及「明显录入错误（如价格为 0 且描述为 NaN）」。

## 问题 4：CustomerID 的「沉默大多数」

**缺失比例**：缺失 Customer ID 的交易占**总行数 24.1%**，但仅占总金额 **17.9%**（金额占比远低于行数占比，说明匿名交易多为小额/低频）。

**差异对比**：
- 国家分布：有 ID 多为 `United Kingdom(3877)、Germany(173)、France(141)、EIRE(79)、Netherlands(65)`；无 ID 多为 `United Kingdom(1227)、Germany(53)、France(42)、EIRE(33)、Netherlands(23)`。
- 客单价（每发票均值）：有 ID ≈ 469，无 ID ≈ 311。
- 高频商品：有 ID 偏好 `M(478)、BANK CHARGES(413)、POST(408)`；无 ID 偏好 `M(146)、D(136)、CRUK(135)`。

**推测**：匿名记录大概率是**游客/线下批发散客**（无注册账号、单次大额拿货），或 B2B 电话/邮件下单未绑定账号。它们不适合做「注册用户 RFM 分群」，但可作为独立的「非会员渠道」单独分析。
